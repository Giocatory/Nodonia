# Нодония — техническая документация

Документ для тех, кто хочет понять устройство симулятора, добавить свой протокол, лабораторную или задание, запустить тесты и опубликовать проект.

## 1. Принципы

- **Только ванильные HTML/CSS/JS.** Нет сборки, пакетного менеджера и бэкенда. Скрипты подключаются обычными `<script>` и работают даже с `file://`.
- **Единое глобальное пространство `ND`.** Каждый файл — IIFE, который добавляет свои части в `window.ND`. Порядок подключения задаёт `nodonia/index.html`.
- **Детерминизм.** Время виртуальное, случайность — только через `rng` (генератор mulberry32 с seed). Один seed + одна история действий = одинаковый результат.
- **Состояние узла — JSON.** `node.st` должно сериализоваться в JSON: на этом основаны шаг назад, сохранение схем и сравнение состояний.

## 2. Структура

```
nodonia/scripts/
  core/util.js      ND.reg (реестры), RNG, куча событий, SHA-256 (синхронный), утилиты
  core/sim.js       ND.Sim — движок дискретных событий
  core/scheme.js    cleanScheme / makeScheme / layout / newSim
  core/console.js   команды консоли (ND.console.exec)
  core/ecdsa.js     ECDSA secp256k1 на BigInt, RFC 6979
  proto/*.js        протоколы: gossip, raft, paxos, pbft, election, twopc, quorum, crdt,
                    clocks, failure, streamlog, pow, pos, services
  chain/*.js        ledger (UTXO и счета), merkle, vm (НодаVM), wallet
  ui/kit.js         ND.ui: h(), modal, toast, store, table, chart, tip, файлы
  ui/timeline.js    пространственно-временная диаграмма
  ui/cluster.js     рабочая область протокола (схема, панели, консоль, задания)
  ui/app.js         меню, рейка разделов, главная, справка, горячие клавиши
  ui/ws-*.js        отдельные рабочие области (хэш, цепь, кошелёк, Меркл, кольцо/DHT, VM, атаки, архитектуры)
  ui/practice.js    лабораторные, задания, тест, экзамен, глоссарий
  content/*.js      данные: лабораторные, задания, вопросы, глоссарий, справка, шаблоны
```

Порядок в `index.html`: core → proto → chain → ui (kit, timeline, cluster, ws-*, practice, app последним) → content.

## 3. Движок (`ND.Sim`)

Схема описывает сеть: `{ proto, params, seed, nodes: [{id,name,x,y,kind,cfg}], links: [{a,b,lat,jit,loss,dup,up}] }`.

Ключевые идеи:

1. **Очередь событий** — бинарная куча по `(время, порядковый номер)`. События: доставка сообщения, срабатывание таймера, запланированное действие.
2. **Сообщения** идут по кратчайшему пути среди работающих каналов; на каждом канале применяются задержка `lat ± jit`, потеря `loss` и дубль `dup`. Если канал рвётся, пока сообщение в пути, оно погибает (`cutBy`).
3. **Сбои**: `crash/recover` узла, `cut/heal` канала, `partition/healall` для разделения сети. Все они — *действия*.
4. **История и воспроизведение.** Каждое действие записывается в `sim.hist` с временем. `Sim.replay(scheme, hist, ev)` строит симуляцию заново и применяет действия в те же моменты; на этом построены «шаг назад» и ссылка «Поделиться».
5. **Инварианты.** После каждого события вызывается `protocol.invariants(sim)`; невыполненные записываются в `sim.violations`.

Основные методы: `start()`, `step()`, `runUntil(tMs)`, `act(kind, args)`, `send(from,to,type,body)`, `setTimer(node,name,ms)`.

Действия (`kind`): `crash`, `recover`, `cut`, `heal`, `partition`, `healall`, `link`, `setcfg`, `setparam`, `client` (действие протокола: `{id, args}`).

## 4. Как написать протокол

Протокол регистрируется вызовом `ND.registerProtocol(p)`. Минимальный пример — «эхо-сервер»:

```js
(function (G) {
  const ND = G.ND;
  ND.registerProtocol({
    id: 'echo', title: 'Эхо', group: 'Основы', order: 99,
    short: 'Узел отвечает на каждое сообщение.',
    desc: '<p>Учебный пример.</p>',
    params: [{ id: 'every', label: 'Период, мс', type: 'number', def: 1000, min: 100, max: 10000 }],
    init(node, sim) { return { got: 0 }; },                    // начальное состояние узла (JSON)
    onStart(ctx) { ctx.timer('tick', ctx.params.every); },
    onTimer(ctx, name) {
      ctx.sendNeighbors('ping', { n: ctx.now });
      ctx.timer('tick', ctx.params.every);
    },
    onMessage(ctx, m) {
      if (m.type === 'ping') ctx.send(m.from, 'pong', {});
      else ctx.st.got++;
    },
    label: node => 'получено ' + node.st.got,                  // подпись у узла
    invariants: sim => [{ id: 'sane', ok: sim.nodes.every(n => n.st.got >= 0), msg: 'счётчик отрицателен' }],
    defaultScheme: () => ND.makeScheme({ proto: 'echo', n: 4, topo: 'full', lat: 50, jit: 10, title: 'Эхо' })
  });
})(window);
```

### Поля протокола

| Поле | Назначение |
|---|---|
| `id`, `title`, `group`, `order`, `short`, `desc`, `legend` | Описание и место в меню. `group` — одна из групп `ND.ui.GROUP_ORDER`. |
| `params` | Глобальные параметры (панель «Протокол»): `number`, `bool`, `select`. Значения — `ctx.params`. |
| `nodeCfg` | Настройки узла (массив или функция от узла). Значения — `node.cfg`. |
| `nodeKinds` | Типы узлов для палитры («клиент», «сервис», …). |
| `actions` | Действия клиента: `{id, label, args, run(sim, args)}`. |
| `init(node, sim)` | Начальное `node.st`. |
| `onStart`, `onMessage`, `onTimer`, `onCrash`, `onRecover`, `onCfg`, `onParam` | Обработчики. `onParam(sim,key)` вызывается при смене параметра на лету. |
| `describe`, `label`, `badge`, `nodeClass`, `ring`, `inspector` | Как узел выглядит и что показывает панель «Узел». |
| `metrics(sim)` | Метрики вкладки «Инварианты и метрики»: `[{label, value}]`. |
| `invariants(sim)` | Проверки безопасности: `[{id, ok, msg}]`. |
| `defaultScheme()` | Схема по умолчанию. |

### Контекст `ctx`

`ctx.node`, `ctx.st`, `ctx.cfg`, `ctx.params`, `ctx.now`, `ctx.sim`, `ctx.rng`, а также `send(to,type,body)`, `bcast(type,body)`, `sendNeighbors`, `timer(name,ms)`, `cancel(name)`, `hasTimer(name)`, `log(text)`, `mark(text,css)`, `peers()`, `neighbors()`.

### Правила

1. Не используйте `Math.random`, `Date.now`, `setTimeout` — только `ctx.rng` и таймеры контекста.
2. `node.st` — только JSON-совместимые данные (без `Map`, `Set`, функций).
3. Глобальные данные протокола храните в `sim.G_<id>` (создавайте лениво), они тоже должны быть JSON-совместимыми.
4. Любое изменение параметров во время работы должно быть безопасным: реализуйте `onParam`, если состояние зависит от параметра.
5. Опишите инварианты — они делают протокол проверяемым и учебным.

## 5. Шаблоны, задания, лабораторные, вопросы

Все они — элементы массивов в `ND.reg`.

**Шаблон схемы**
```js
ND.reg.templates.push({ id: 'raft-5', proto: 'raft', title: 'Raft: 5 узлов', desc: '...',
  build: () => ND.makeScheme({ proto: 'raft', n: 5, topo: 'full', lat: 40, jit: 15 }) });
```

**Задание с автопроверкой** (`content/tasks.js`):
```js
{ id, title, proto, level, text, scheme: () => ..., hints: [...],
  goals: [{ t: 'Описание цели', w: 2, check: sim => boolean }] }
```
Функция `check(sim)` вызывается несколько раз в секунду. Она должна быть быстрой и не изменять состояние. Тест `content_tasks.js` требует, чтобы у каждого задания было решение «как у студента» — добавляйте решение в тест.

**Лабораторная** (`content/labs-*.js`): `{ id, title, group, proto | ws, template?, level, time, goal, theory (HTML), steps[], questions[[вопрос, ответ]] }`.

**Вопрос теста** (`content/quiz.js`): `Q(тема, вопрос, верный, неверный1, неверный2, неверный3, пояснение)`. Порядок вариантов перемешивается при показе.

**Глоссарий** (`content/glossary.js`): пары «термин — определение».

## 6. Рабочие области

`ND.ui.registerWorkspace({ id, title, group, order, short, mount(root, opts) })`. Открытие: `ND.ui.open('w:<id>')` или `ND.ui.open('p:<протокол>', { scheme, task })`. Хэш-маршрутизация: `#p=raft`, `#w=vm`. Ссылка «Поделиться» кодирует схему в `#s=<base64 JSON>`.

Рабочая область протокола (`ui/cluster.js`) возвращает объект управления (`toggle`, `stepFwd`, `stepBack`, `resetSim`, `getSim`, `getScheme`, …), который используют меню и горячие клавиши.

### Сравнение протоколов (`ui/ws-compare.js`)

Движок `ND.compare` не зависит от DOM. Адаптер протокола (`ND.compare.ADAPT`) задаёт, как отправить запрос клиента (`submit`), какой узел главный (`primary`) и как понять, что узел принял решение (`decided`). Сценарий (`SCENARIOS`) — сеть и отказы. `compare({scenario, n, seeds, horizon, k, retry, protos})` прогоняет каждый протокол с одинаковыми seed 1…S: прогрев 8 с, затем запрос; наблюдение шагом 25 мс виртуального времени. Результат — медианы времени до первого решения, до большинства и до всех живых, число сообщений до решения, исходы (✔ решено, ↩ откат, ⛔ блокировка, ✘ нет решения) и нарушения инвариантов. `recipe(pid, opts)` выдаёт команды консоли для ручного воспроизведения. Чтобы добавить протокол, достаточно записи в `ADAPT`; тест — `tests/cases/net_compare.js`.

## 7. Блокчейн-модули

- `core/ecdsa.js` — ECDSA на secp256k1 (BigInt), детерминированный nonce по RFC 6979; проверены на известных тестовых векторах.
- `chain/merkle.js` — дерево Меркла и доказательства включения.
- `chain/ledger.js` — модели UTXO и счетов, PoW-майнинг, проверка блоков.
- `chain/vm.js` — стековая виртуальная машина «НодаVM»: газ, хранилище, откат при ошибке, примеры контрактов (в том числе уязвимых).
- `ui/ws-attack.js` экспортирует чистую математику `ND.attackMath`: формула Накамото, точный Монте-Карло, эгоистичный майнинг (Eyal–Sirer), устаревшие блоки, эмиссия, пересчёт сложности.

## 8. Тесты

```bash
node tests/run_all.js
```

Тесты загружают скрипты в изолированный `vm`-контекст (`tests/load.js`), без DOM. Что проверяется:

- безопасность протоколов (`proto_*`): единственный лидер в терме, согласованность решений, а также сценарии, где безопасность **должна** нарушаться (нарушение допущений f);
- воспроизводимость: одинаковый seed → одинаковая история, replay совпадает с прямым прогоном;
- криптография: векторы ECDSA/SHA-256, цепочки, дерево Меркла, ВМ;
- математика: формула Накамото на справочных значениях, Монте-Карло против точного результата;
- контент: у каждого задания есть решение, у каждой лабораторной существуют шаблон и протокол.

Смоук-тест интерфейса (`tests/ui_smoke.js`, Playwright + Chromium) открывает каждый раздел и проверяет отсутствие ошибок в консоли.

## 9. Публикация

Скопируйте каталог на любой статический хостинг. `.htaccess` (Apache) включает кэширование, сжатие и заголовки безопасности. Для nginx перенесите правила вручную. Лендинг настраивается в `scripts/config.js`.

## 10. Известные ограничения

- Протоколы упрощены: нет диска и сжатия журналов, а размеры сети ограничены десятками узлов.
- Сетевая модель идеализирована: нет перегрузки каналов и очередей на узлах (кроме модели `services`).
- Время виртуальное: «скорость» зависит от выбранного множителя и мощности устройства.
- Криптография учебная; не используйте её для защиты реальных данных.
